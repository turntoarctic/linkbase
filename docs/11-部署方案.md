# 11 - 部署方案

> 权威文档：部署拓扑、环境变量、Dockerfile、备份。单机 Docker Compose（04 §6 约束），多实例/云部署不在本期。

## 1. 拓扑

```
                    ┌──────────────────────── host ────────────────────────┐
 :80/:443           │                                                      │
   │                │   ┌───────────────────────────────┐                 │
 用户 ──────────────┼──▶│  app（Bun + Hono，容器内 :3001）│                 │
                    │   │  /api/*  /ws  + 静态 dist      │                 │
                    │   └───────────────┬───────────────┘                 │
                    │        ┌──────────┴──────────┐                       │
                    │        ▼                     ▼                       │
                    │  ┌───────────┐         ┌─────────┐   ┌──────────┐   │
                    │  │postgres 18│         │ redis 8 │   │ volumes  │   │
                    │  │  :5432    │         │  :6379  │   │ (见 §4)  │   │
                    │  └───────────┘         └─────────┘   └──────────┘   │
                    └──────────────────────────────────────────────────────┘
```

- **单一对外入口**：app（Bun/Hono）同进程托管前端静态产物（Vite `dist`）、`/api/*` 与 `/ws`，**不再需要 nginx 反代**；Bun 原生 WebSocket 直接处理 `/ws`；
- 静态资源与 SPA fallback 由 Hono `serveStatic` 处理（`static.ts`，未知路径回落 `index.html`）；
- TLS 由宿主前置（云 LB 或 certbot 挂证书），容器内不处理 443。

## 2. docker-compose.yml（骨架，以实施日为准）

```yaml
services:
  app:
    build: { context: ., dockerfile: docker/app.Dockerfile }
    ports: ["80:3001"]            # 全栈唯一暴露端口（容器内 Bun 监听 3001）
    environment:
      DATABASE_URL: postgresql://${POSTGRES_USER}:${POSTGRES_PASSWORD}@postgres:5432/${POSTGRES_DB}
      REDIS_URL: redis://redis:6379
      JWT_SECRET: ${JWT_SECRET}
      APP_ORIGIN: ${APP_ORIGIN}          # 如 https://linkbase.example.com
      FRONTEND_URL: ${APP_ORIGIN}        # CORS 白名单（同源部署可与 APP_ORIGIN 相同）
      PORT: "3001"
      LOG_LEVEL: info
    depends_on:
      postgres: { condition: service_healthy }
      redis: { condition: service_healthy }
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://localhost:3001/api/health"]
      interval: 15s
      timeout: 5s
      retries: 5
  postgres:
    image: postgres:18-alpine
    environment:
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}   # 注意：官方镜像只有 *_USER/*_PASSWORD/*_DB
      POSTGRES_DB: ${POSTGRES_DB}
    volumes: [pgdata:/var/lib/postgresql/data]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}"]
      interval: 10s
      retries: 10
  redis:
    image: redis:8-alpine
    volumes: [redisdata:/data]
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
volumes: { pgdata: {}, redisdata: {} }
```

## 3. 镜像构建

统一模式：`oven/bun:1-alpine` + 多阶段（deps → build → runtime）。Bun 直接执行 TS，服务端**无编译产物**，只对前端跑 Vite 构建。**本地源码集成注意**：vendored 的 `packages/blocksuite/` 就在应用仓库内，天然处于构建上下文中（.dockerignore 勿排除 `packages/`）。

- `docker/app.Dockerfile`：
  1. deps 层：`bun install --frozen-lockfile`（workspace 一次装齐）；
  2. build 层：`bun run --filter web build` 产出 `apps/web/dist`（Vite 把 vendored BlockSuite TS 源码编译进产物）；
  3. runtime 层：拷 root `package.json` + `bun.lock` + `node_modules` + `apps/server` + `packages` + `apps/web/dist`，`CMD ["bun","run","apps/server/src/index.ts"]`（迁移在启动时自动执行，07 §2）；
- 不需要 server 的 `tsc` 构建步骤；typecheck 只在 CI/本地质量门执行；
- **体积优化（可选）**：runtime 用 `bun build apps/server/src/index.ts --target=bun --outfile=server.js` 打成单文件，只拷 `server.js` + `apps/web/dist`，避免把 `packages/blocksuite/` 源码与 devDependencies 带进运行镜像（BlockSuite 仅在 web 构建阶段需要）。

环境变量唯一清单（新增先登记于此）：

| 变量 | 用途 |
|------|------|
| `DATABASE_URL` | PG 连接串（唯一数据库配置来源） |
| `REDIS_URL` | Redis 连接串（唯一，代码不得再读 REDIS_HOST/PORT 散变量——旧方案断链教训） |
| `JWT_SECRET` | Access token 签名（≥32 字节随机） |
| `APP_ORIGIN` | 对外域名（邀请链接拼接） |
| `FRONTEND_URL` | CORS 白名单来源（同源部署可等于 APP_ORIGIN） |
| `PORT` | app 监听端口（默认 3001） |
| `LOG_LEVEL` | Pino 级别 |
| `POSTGRES_USER/PASSWORD/DB` | 仅 compose 内 PG 初始化用 |

## 4. 数据与备份

| 卷 | 内容 | 备份策略 |
|----|------|----------|
| `pgdata` | 全部业务数据（含 blob） | 每日 `pg_dump -Fc` 到 `/backups`（宿主 cron 或独立 backup 容器），保留 14 天，每周异地同步一次 |
| `redisdata` | 会话/邀请/票据/限流 | **不备份**（全部可重建：用户重登、邀请重发），文档明示接受 |

恢复演练：备份文件在测试环境 `pg_restore` + 冒烟用例，纳入 P1 检查单（不口头承诺）。

## 5. 开发环境

- `bun dev`：web（Vite 5173，proxy `/api`→3001、`/ws`→3001）+ server（`bun --watch apps/server/src/index.ts`）；PG/Redis 用 `docker compose -f docker/compose.dev.yml up -d`（仅数据库两服务）；
- 依赖与 workspace 配置（`bunfig.toml`、`catalog`、`overrides`、`trustedDependencies`）见 07 §2.1；`bun install` 锁 `bun.lock`；
- 首次：`bun install && bun run db:migrate && bun dev`；
- e2e：`docker compose -f docker/compose.e2e.yml` 全栈 + Playwright。

## 6. 发布流程（P0 极简版）

1. 本地：`bun run typecheck && bun run test && bun run e2e` 全绿；
2. 构建：`docker compose build`；
3. 上线：`docker compose up -d`（迁移随启动执行；PG 大版本升级前必须先备份并单测 `pg_restore`）；
4. 验证：`/api/health` 返回 ok、登录+建页+编辑冒烟。

回滚：镜像按 git sha 打 tag，`docker compose` 指定旧 tag 重起；迁移不写 down（破坏性迁移必须双发布兼容，先加后删）。

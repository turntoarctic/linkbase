# 07 - 后端架构

> 权威文档：后端分层、中间件、认证会话、错误与日志、测试。API 端点清单见 10，表结构见 08，部署见 11。

## 1. 原则

1. **Hono 直用，函数式**：无 DI 容器、无装饰器、无 class 注入。路由 = Zod 校验 → 调 service → 组装响应；service = `(db, input) => Promise<output>` 纯函数。
2. **Bun 运行时 + 全仓 ESM**：`"type": "module"`；Bun 原生执行 TS，无需编译产物；tsconfig 用 `module: Preserve` + `moduleResolution: bundler`，相对导入不必写 `.js` 后缀（typecheck 用 `tsc --noEmit`）。
3. **PostgreSQL 唯一数据库**，Drizzle ORM（`drizzle-orm/bun-sql` + `Bun.SQL` 原生驱动，`packages/database`）。**Redis 只做会话/邀请/WS 票据/限流缓存**，不承载业务数据（丢失可重建，见 §6）。
4. 一个 `Bun.serve` 进程提供 REST + WebSocket + 前端静态产物（Bun 原生 WebSocket，见 09），不拆服务、不需要 nginx。
5. 请求校验只用 Zod（`@linkbase/contracts` 与前端同源）+ `@hono/zod-validator`，不用 JSON Schema 双轨。

## 2. 目录结构

```
apps/server/src/
  index.ts            # 启动：Bun.serve({ fetch: app.fetch, websocket })；优雅停机
  app.ts              # Hono 实例组装：注册中间件与路由
  env.ts              # Bun.env 读取 + zod 校验，启动失败即退出
  middleware/
    auth.ts           # JWT 鉴权中间件 + c.set('user', ...) 注入
    workspace.ts      # 工作空间成员校验中间件（03 §3）
    error.ts          # app.onError 统一错误处理（AppError → 响应结构）
    rate-limit.ts     # Redis 计数限流（登录/注册更严）
    logger.ts         # 结构化请求日志（含 reqId，响应头回传）
  routes/
    auth.ts           # /api/auth/*
    users.ts          # /api/users/*
    workspaces.ts     # /api/workspaces/*（含成员、邀请接受）
    pages.ts          # /api/workspaces/:wsId/pages/*
    doc.ts            # /api/workspaces/:wsId/pages/:pageId/doc（BlockNote JSON，05 §2）
    blobs.ts          # /api/workspaces/:wsId/blobs、/api/blobs/:id
    tags.ts           # /api/workspaces/:wsId/tags/*
    search.ts         # /api/workspaces/:wsId/search
    health.ts         # /api/health
  services/           # 纯函数业务逻辑（auth/pages/docs/tags/search/...）
  db/
    index.ts          # drizzle 实例（Bun.SQL 连接，内置连接池）
    redis.ts          # Bun 原生 Redis 客户端（会话/邀请/票据/限流）
    migrate.ts        # 启动时跑迁移（drizzle-kit 生成的 SQL）
  jobs/
    trash-cleanup.ts  # 每日定时：回收站 30 天清理
    snapshot-merge.ts # 快照合并任务（08 §4.3）
  ws/
  static.ts           # 托管 apps/web/dist（SPA fallback 到 index.html）
  lib/                # editor-meta（BlockNote content 派生提取）、tokens、errors 等纯函数
```

### 2.1 仓库与依赖配置（Bun workspace）

- **workspace 声明**：根 `package.json` 的 `workspaces`（`apps/*`、`packages/*`），不再用 `pnpm-workspace.yaml`；
- **`bunfig.toml`**：`[install] saveTextLockfile = true`（提交可读 `bun.lock`）、`[run] bun = true`（脚本用 Bun 运行时）、可选供应链 `minimumReleaseAge`；生命周期脚本白名单在根 `trustedDependencies`（Bun 默认不跑依赖脚本）；
- **版本统一用 `catalog`**：根 `package.json` 顶层 `catalog`（默认目录）集中声明版本，workspace 依赖写 `"catalog:"`；升级只改一处；
- **`overrides` 钉死单实例**：`react`、`react-dom`（06 §1.1）；合并前跑 `bun pm ls` 校验；
- **脚本**：`dev`（并行起 web+server）、`build`、`typecheck`、`test`、`db:*` 全部 `bun run`。

## 3. 中间件

Hono 中间件按注册顺序执行，等价于旧 Fastify 插件；全局关注点：

| 关注点 | 方案 |
|--------|------|
| CORS | `hono/cors`，白名单 = 同源 + `FRONTEND_URL`；MVP 同源部署可直接关 |
| 安全头 | `hono/secure-headers`（CSP、HSTS、X-Frame-Options 等默认集） |
| 体量限制 | `hono/body-limit`：JSON ≤ 1MB；doc/blob 二进制端点单独放宽（doc update 512KB/次、blob 25MB）；`Bun.serve.maxRequestBodySize` 兜底 |
| 限流 | 自定义 Redis 计数中间件（`INCR` + `EXPIRE` 固定窗口）：全局 100 次/15min/IP；`/auth/login` 5/min、`/auth/register` 3/h。跨实例共享计数；Redis 不可用时启动告警并按进程内存降级（仅开发） |
| 请求日志 | 结构化 JSON（Pino 独立依赖，Bun 兼容；stdout 直出不启用 worker-thread transport），`redact` 掉 Authorization/密码字段；每请求生成 `reqId` 并经响应头返回 |
| 鉴权 | `middleware/auth.ts` 验 JWT → `c.set('user', { id })`；工作空间级路由再过 `middleware/workspace.ts` 查 `workspace_members`（03 §3，不缓存） |

## 4. 错误处理

```ts
export class AppError extends Error {
  constructor(readonly code: string, readonly status: number, message: string,
              readonly details?: unknown) { super(message); }
}
// app.onError 统一兜底：
// AppError → { error: { code, message, details } }
// ZodError（@hono/zod-validator 包装后）→ 400 LB_VALIDATION，details 为 issue 列表
// 其余 → 500 LB_INTERNAL，日志记 stack，响应不带内部信息
```

错误码全集见 10 §6。服务层只 throw `AppError`，路由层不拼错误响应。

> i18n：`message` 仅作开发兑底，客户端按 `code` 本地化（13 §4）；服务端日志/内部消息用英文，不参与 i18n。

## 5. 认证与会话

| 项 | 决策 |
|----|------|
| 密码 | `Bun.password`（原生 Argon2id，无需 bcrypt 依赖） |
| Access Token | JWT（`hono/jwt` 的 `sign`/`verify`），HS256，15 分钟，payload `{ sub, wid? }`（wid=当前工作空间，用于 doc 端点鉴权加速，可缺省） |
| Refresh Token | 不透明随机串（非 JWT），256bit，存 Redis `refresh:{token} → {userId, workspaceId?}` TTL 7 天；使用时**旋转**（旧的删除、发新的） |
| 存储 | Access → 前端内存 + localStorage（接受 XSS 权衡，MVP 不引第三方 Cookie 域）；Refresh → localStorage |
| 登出 | 删除 Redis refresh 记录（Access 自然过期） |
| 鉴权 | `auth.ts` 验 JWT → `c.set('user', { id })`；工作空间级路由再查 `workspace_members` |
| 注册 | 限流 3/h/IP（与 §3 一致）；成功后自动建工作空间 + 快速开始页（02 §1.1、§3），直接返回两 token |

## 6. 定时任务与状态边界

- **定时任务**：进程内轻量调度（`setInterval` + 启动随机延迟错峰，不引 cron 库）：
  - **trash-cleanup**：每小时扫 `pages.is_trash && deleted_at < now()-30d`，物理删除（连带 updates/snapshots/tags/favorites，blob 引用计数检查后清理孤儿附件）；
  - **snapshot-merge**：见 08 §4.3。
  - 任务必须幂等，日志记录每次执行结果。
- **Redis 边界**：只放可重建的瞬时/会话数据（会话、邀请、WS 票据、限流计数），**绝不承载业务真相**；Redis 数据丢失的后果仅为用户重登、邀请重发、票据失效。WS 房间仍在进程内存（单实例部署；横向扩展见 09 §7）。

## 7. WebSocket

Bun 原生 WebSocket 经 `hono/bun` 的 `upgradeWebSocket` 挂 `/ws`——实时协作暂缓（09 ⚠️，05 §7；BlockNote 协作模式为既定演进），MVP 不注册该路由；文中票据设计留作将来参考。

## 9. 可观测性（P0 最小集）

- `/api/health`：检查 PG `select 1` 与 Redis ping，返回各自 ok/fail（供 docker healthcheck 与探活）；
- 结构化日志输出 JSON（Pino），生产直接给 docker 收集，不做额外 APM（P2 再议）；
- 关键业务计数打点（编辑器 update 接收量、快照合并次数）先只进日志。

## 10. 待细化

- Refresh Token 多端并存策略（每端一条记录 vs 全局单条）——倾向每端一条（device name 标记），Phase 1 实现时定；
- doc 端点防滥用（恶意高频 push 小 update）——限流阈值实测后定；
- 优雅停机细节（在飞请求排空 + WS 房间关闭广播）随 Phase 2 落。

# Linkbase 设计文档

**Linkbase = 面向研发团队的 Notion**：一个万物基于 Block 的协作知识库。注册即可落笔写页面，PRD、技术设计、API 文档、测试计划都是「页面 + 块」，研发特化能力（API 块、Mock、AI）以扩展块与模板渐进叠加。

---

## 技术基线（全文档唯一口径）

| 层 | 选型 |
|------|------|
| 编辑器 | **BlockSuite**（Yjs 原生块编辑框架，Web Component 接入）——**本地源码集成**：源码包 vendor 进应用仓库 `packages/blocksuite/`，作为 workspace 本地包直接使用（不装 npm 包），可断点调试、可改，方案见 05 |
| 前端 | React 19 + TypeScript + Vite 8 + Tailwind CSS 4 + shadcn/ui（Base UI）+ TanStack Query + react-router + i18next（zh-CN/en，见 13），界面风格对标 Notion；**版本与兼容红线见 06 §1.1**（yjs 单实例优先） |
| 后端 | **Hono**（运行于 Bun，函数式路由/中间件，无 DI / 无装饰器）+ Zod 校验 |
| 数据库 | **PostgreSQL 唯一数据库**（Drizzle ORM，`Bun.SQL` 原生驱动），Redis（会话/邀请/票据/限流） |
| 协作 | Yjs 协议 + Bun 原生 WebSocket，内容存储即 Y.Doc（增量 updates + 快照） |
| 部署 | Docker Compose 单机：app(Bun/Hono，同进程托管静态 + API + WS) + postgres + redis |

**版本策略**：全部依赖使用**当前最新稳定版**（Bun latest、React/Vite/TS/Tailwind/Hono/Drizzle/Zod 均以实施当日 npm latest 为准并锁定 lockfile）。BlockSuite 是唯一例外：不装 npm 包，源码包 vendor 为 `packages/blocksuite/` 本地包（基线 0.22.4），升级 = 从上游克隆同步 diff + fixup + 全量回归。

## 文档维护规则

- **单一事实源**：每个决策只在一篇权威文档中定义，其他文档只引用不重复。表结构只在 08、API 只在 10、环境变量只在 11。
- **显式待细化**：未决内容统一放在各文档末尾「待细化」小节，用 `待细化` 标记，可全局 grep 追踪；定稿后移除标记。禁止隐性留白（空实现、假代码）。
- **变更流程**：架构级变更先改本 README 的技术基线表 + 对应权威文档，再同步受影响文档；同时在 91 记一条变更。
- 91 每次开发会话后更新；90 的任务状态以 91 为准，不在 90 内单独维护状态列。
- 旧版文档见 [archive/](archive/README.md)，仅作领域细节参考，不作为实现依据。

# 13 - 国际化设计（i18n）

> 权威文档：语言范围、技术选型、前后端文案归属、BlockSuite 编辑器 UI 的处理。技术栈见 06，错误码见 10 §6，表结构见 08。

## 1. 目标与范围

Linkbase 面向研发团队，默认中文、同时支持英文。**只翻译「系统文案」，不翻译「用户内容」**：

| 对象 | 是否 i18n |
|------|-----------|
| 应用 chrome（登录、侧边栏、设置、按钮、提示、空状态） | ✅ 我们负责，全量 i18n |
| API 错误/系统消息 | ✅ 稳定错误码 + 客户端本地化（§4） |
| 用户写的页面内容（块树/Y.Doc） | ❌ 永远原样，不做机器翻译 |
| BlockSuite 编辑器内置 UI（slash 菜单、tooltip、工具栏） | ⚠️ 上游无 i18n，按 §5 分层处理 |

- 首发语言：**`zh-CN`（默认）**、**`en`**；资源按命名空间拆分，后续加语言只加目录。
- 语言是**用户偏好**，不进 URL（不做 `/zh/` 前缀），保证页面链接稳定。

## 2. 技术选型与兼容性

| 项 | 选型 | 说明 |
|----|------|------|
| 核心 | **i18next 26.x** | 成熟、React 19 兼容、命名空间与懒加载 |
| React 绑定 | **react-i18next 17.x** | peer：`react >= 16.8`、`i18next >= 26.2`、`typescript ^5||^6||^7` |
| 语言探测 | **i18next-browser-languagedetector 8.x** | `navigator.language` 兜底 |
| 类型化 key | **i18next-resources-for-ts 2.x**（dev） | 由 zh-CN 资源生成 key 联合类型 |
| 数字/日期 | **原生 `Intl.*`** | 不做第三方格式化依赖 |

**不引入 ICU 插件（兼容性红线）**：`i18next-icu@2.4` 的 peer 要求 `intl-messageformat >=10.3.3 <12.0.0`，而当前 latest 已是 12.x，两者冲突。改用 i18next 原生插值 + 复数（`_one`/`_other`）+ 原生 `Intl` 处理日期/数字/相对时间。

> 备选（未采用）：Lingui 6（编译期提取，产物小，但需额外 Babel/Vite 集成与 `.po` 流程）；MVP 不引入第二套运行时。

## 3. 前端结构

```
apps/web/src/i18n/
  index.ts            # i18next 初始化（resources、fallbackLng、detector）
  formatters.ts       # useFormatters：Intl.DateTimeFormat / NumberFormat / RelativeTimeFormat
  locales/
    zh-CN/{common,auth,workspace,editor,errors}.json
    en/{common,auth,workspace,editor,errors}.json
```

- `main.tsx` 挂 `<I18nextProvider>`（与 Query/Router 同层）；组件一律 `useTranslation()`，**禁止硬编码 UI 文案**（§7 有检查脚本）。
- 命名空间：`common`（通用词）、`auth`、`workspace`（树/标签/搜索）、`editor`（自有编辑器外壳）、`errors`（错误码映射）。
- **探测与持久化优先级**：登录用户 `users.locale`（08 §3.1）→ `localStorage('linkbase.locale')` → `navigator.language` → 兜底 `zh-CN`。切换语言时写回 localStorage，登录态再 PATCH 到用户资料。
- 同步 `<html lang="zh-CN">`（无障碍与字体回退）。
- 日期/数字/相对时间一律走 `useFormatters()`，不手写格式；时区取浏览器。

## 4. 后端与 API

- **服务端不返回本地化文案作为契约**：响应体 `{ error: { code, message, details } }`（10 §4）中 `message` 仅作开发兜底；**客户端按 `code` 映射到 `errors` 命名空间**，保证同一 code 在任何语言下文案一致。
- 错误码 → i18n key 的映射集中在 `packages/contracts`（与 code 同源），前端取用；新增 code 必须同时加 zh/en 文案（§7 校验）。
- `Accept-Language` 请求头：服务端当前不产生面向用户的持久文本（无邮件/通知），**暂不使用**；将来若发邮件再按它选模板。
- DB：`users.locale`（`text`，可空，如 `zh-CN`/`en`）作为跨端偏好；未登录用户仅 localStorage。
- 服务端日志/内部消息用英文，不参与 i18n（面向开发者）。

## 5. BlockSuite 编辑器 UI（关键兼容点）

**已验证事实（2026-09-29，vendored 0.22.4 源码核对）**：BlockSuite 源码中**没有 i18n 基础设施**（无 i18n provider / locale 资源包），编辑器内置文案为**硬编码英文**，例如 `packages/blocksuite/affine-widgets/slash-menu/src/config.ts` 的 `name: 'Today' | 'Delete' | 'Duplicate' …`。

分层策略（**不在上游做全量翻译**——成本高且每次同步都冲突）：

| 层 | MVP（P0） | P1 桥接 |
|----|-----------|---------|
| 应用 chrome | ✅ 全量 zh-CN/en | — |
| 自有编辑器外壳（页面标题、页菜单、导图工具栏等） | ✅ 我们本地化 | — |
| BlockSuite 内置 UI | ⚠️ **接受英文**，文档明示 | 通过扩展点注入中文：优先 slash-menu config / 自定义块等可覆盖入口；无法覆盖的关键字符串才改 vendored 源码，并在 91 §5 登记最小 diff |
| 自研扩展块（API 块等，P2） | — | ✅ 自带 i18n，进 `editor` 命名空间 |

**Phase 0 验证任务（T0.9）**：✅ 已完成（2026-09-29，vendored 0.22.4 源码核对），清单如下。

### 5.1 扩展点机制事实（0.22.4）

无 i18n 基础设施；文案全部硬编码。文案可达性由三种 DI 机制决定：

| 机制 | 语义 | 例子 |
|------|------|------|
| `ConfigExtensionFactory` | **override（可整体替换）** | 段落 placeholder、@ 提及菜单（`getMenus`） |
| `SlashMenuConfigExtension` | `getAll` + flatMap **合并（只能追加）** | slash 菜单：可加自定义项，不可改名默认项 |
| `ToolbarModuleExtension` | `addImpl` + `getAll().get()` 取**先注册者** | 各块工具栏：外部注册会重复按钮，不可覆盖 |

### 5.2 桥接清单（三类）

**✅ 可覆盖（扩展点注入，零 diff）**

| 字符串面 | 入口 | 备注 |
|------|------|------|
| 段落空态 placeholder（「输入文字，输入 '/' 唤起菜单」等） | `ParagraphBlockConfigExtension({ getPlaceholder })` | view.ts options zod 校验，整体替换 |
| @ 提及菜单（“链接到文档/新建文档”分组） | `LinkedWidgetConfigExtension({ getMenus })` | 返回自建中文菜单组即可 |
| slash 菜单**追加**自定义项（自研块/命令） | 额外注册 `SlashMenuConfigExtension('linkbase', …)` | 与默认项合并展示 |

**🔧 须改源码（最小 data 级 diff，登记 91 §5）**

| 文件 | 内容 | 量级 |
|------|------|------|
| `affine-widgets/slash-menu/src/config.ts` | 默认项 name/description/alias（Text/Heading/Todo/…≈40 项） | 中 |
| 各块 `configs/toolbar.ts`（attachment/bookmark/image/embed/inline link 等） | Rename/Download/Duplicate/Delete/Caption 等 tooltip/按钮 | 中 |
| `affine-blocks/code/src/code-toolbar/config.ts` | 「Copy code」等工具栏项 | 小 |
| `affine-inlines/preset/src/command/config.ts` | Bold/Italic… name（进 slash 菜单与快捷键提示） | 小 |
| `affine-data-view/src/property-presets/*/define.ts` | 列类型名（Select/Number/Date/…；`DatabaseBlockConfigService` 是**死代码**，上游注册方未消费，不可依赖） | 中 |
| data-view/database 零散 toast 与确认框（“Copied to clipboard” 等） | 散点 | 小 |

**🚫 放弃（接受英文）**

- Edgeless 全套工具栏/gfx 文案（P1-T2.7 打磨时再评估）；
- `keyboard-toolbar`（移动端软键盘工具栏，Linkbase 桌面优先）；
- tooltip 里的 SVG 示意图（内嵌 `<text>` 属插画，非 UI 文案）；
- 代码块语言名（shiki 语言专有名词，保持英文合理）。

**工作量结论（P1-8 依据）**：P0 文档模式范围 = 上表 🔧 前 4 行 + data-view 列类型，均为**纯数据字符串替换**，估计数百行、一次 PR 级；代价在 vendor 同步需 rebase（05 §8），建议 Phase 1 收尾时一次性做完，T2.9 只收残项。另：doc-title 片段**无 placeholder 文案**（空标题纯留白），无需处理。

## 6. 语言切换

- 入口：设置 → 通用（语言）；登录页右上角也给一个轻量切换（未登录可用）。
- 切换即 `i18n.changeLanguage()`，React 树重渲染，**不刷新页面**；已打开的 BlockSuite 编辑器实例与 Y.Doc 不重建（内容与语言无关）。
- 落库：登录态 `PATCH /users/me { locale }`（10 §2.1），失败仅告警不影响本地切换。

## 7. 测试与守护

1. **无硬编码文案**：脚本扫描 `apps/web/src` 的 JSX 文本节点与常见属性（`title`/`placeholder`/`aria-label`），命中即失败（白名单：品牌名 Linkbase、代码块样例）。
2. **key 对齐**：zh-CN 与 en 的 key 集合必须一致（多余/缺失都报错）；由 `i18next-resources-for-ts` 生成类型，编译期兜底拼写错误。
3. **错误码覆盖**：`packages/contracts` 的每个 `LB_*` 码在两个语言的 `errors` 中都有文案（10 §6 × 13 §4）。
4. **e2e**：切换语言后登录页/侧边栏/设置关键文案随语言变化（Playwright）。

## 8. 待细化

- 是否首发即提供 `en` 全量文案，还是 `en` 先覆盖 P0 页面、其余回退 zh（倾向后者，避免半成品）。
- 服务端邮件/通知（后期）的 `Accept-Language` 与模板方案。
- BlockSuite 桥接清单与最小 patch 集（T0.9 产出后回填 §5）。
- 术语表（Glossary）统一「页面/块/工作空间/回收站」等中英对照，避免不同译者不一致。

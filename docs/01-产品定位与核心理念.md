# 01 - 产品定位与核心理念

> 权威文档：产品定位。其他文档引用本文，不重复定义。

## 1. 一句话定位

**Linkbase 是面向研发团队的 Notion**——一个万物基于 Block 的协作知识库。它首先是一个极好用的文档工具：注册、落笔、写作，没有任何前置仪式；在此之上，通过**扩展块**与**页面模板**把研发场景（PRD、技术设计、API、测试、AI 辅助）逐块叠加进来。

## 2. 核心理念

### 2.1 打开即写，零仪式

旧版设计要求「创建工作空间 → 创建项目 → 创建需求」三步才能落笔，这是本产品被否决的原因。新版遵循 Notion 模式：

- 注册成功即自动拥有一个工作空间（无感，可随时改名）；
- 首屏直接是一篇可编辑的《快速开始》页面，光标已在正文闪烁；
- 组织方式由用户自己长出来：子页面、标签、收藏，而不是系统预设的容器。

**任何功能都不得强迫用户先建容器再建内容。**

### 2.2 万物基于 Block

页面是唯一的内容容器，页面内部是一棵块树（BlockSuite / Yjs）。由此推出一组硬规则：

| 规则 | 含义 |
|------|------|
| 一切内容皆页面 | PRD、技术设计、会议纪要、API 文档——都是页面，只是模板与块不同 |
| 一切结构皆块 | 表格、看板（后期 database 块）、嵌入引用、代码、图片——都是块 |
| 引用优于复制 | 页面间引用使用链接块（linked doc），被引用处自动形成反向链接（后期） |
| 内容即 Y.Doc | 每个页面是一个 Yjs 文档；服务端存储增量 updates 与快照，不再有 `document_blocks` 关系表 |
| 研发能力是块 | 后期的 API 块、Mock 块、测试用例块都是普通扩展块，不是独立子系统 |

### 2.3 协作是一等公民

BlockSuite 以 CRDT（Yjs）为原生数据流，多人实时协作、离线编辑、历史版本都不是「后期插件」，而是存储模型自带的属性。MVP 先跑单人编辑 + 多端同步，实时多人随 Phase 2 打开。

### 2.4 AI 作用于页面上下文

AI 能力（Phase 3+）以页面为单位消费与产出：选中块改写、基于整页生成测试计划、PRD 生成技术设计草稿。AI 产物一律以**草稿块/草稿页面**落盘，人工确认后生效。

## 3. 与旧模型的决裂点

| 旧版（已归档） | 新版 | 理由 |
|----------------|------|------|
| Workspace → Project → Requirement 三级实体 | Workspace → Page 两级 | 消灭创建仪式；组织靠页面树 + 标签 |
| Project 实体（含 Key、状态） | 页面树的分组 + 标签 | 「项目」只是若干页面的一个标签或一个父页面，不是实体 |
| Requirement 实体 + 专用状态机 | 模板页面（PRD 模板）+ database 视图（后期） | 需求就是一篇结构化页面 |
| PRD/API/Mock/Test 各自的表与模块 | 扩展块 + 模板，渐进实现 | 底层复杂度收敛到块模型 |
| Tiptap + 自研 Block 存储表 | BlockSuite，内容即 Y.Doc | 不重复造块引擎；天然协作 |
| 关系表 relations（7 种关系类型） | 链接块（linked doc），反链自动生成 | 引用是内容的一部分，不是旁路数据 |

## 4. 产品原则（写代码前先过一遍）

1. **快**：编辑器本地操作零网络等待，同步在后台进行；首屏 < 1.5s。
2. **简**：UI 只保留一个主操作入口（新建页面），其余能力通过 `/`（slash）与 `⌘K` 涌现。
3. **稳**：数据不丢——每次编辑生成 Yjs update，先本地后服务端，断网可继续写。
4. **美**：界面完整对标 Notion 的克制与精致（见 06），细节不将就。

# 12 - AI 能力规划

> 定位：**Phase 3（P2）规划文档，刻意保持薄**。立项时按本文件原则扩写为详细设计（新文档），不提前写代码与 Prompt 细节。

## 1. 定位

AI 不做聊天窗，做「页面上下文的写作者」：所有能力围绕当前页面/选中块展开，产物回到页面里继续被人编辑。

## 2. 能力清单（按价值排序，届时逐个立项）

| # | 能力 | 输入 → 输出 |
|---|------|-------------|
| A1 | 块级改写 | 选中文本块 → 润色/翻译/缩写/扩写，结果**预览替换**（可拒绝） |
| A2 | 整页生成大纲 | 标题 + 空页 → 生成结构草稿（标题层级 + 段落要点） |
| A3 | 模板内容生成 | PRD 模板页 → 按「用户故事/验收标准」小节生成草稿内容 |
| A4 | PRD → 测试计划 | PRD 页（含 Given/When/Then 块）→ 新建「测试计划」页面（草稿） |
| A5 | PRD → 技术设计草稿 | PRD 页 → 技术设计模板页草稿 |
| A6 | 工作空间问答 | 全空间搜索召回 → 带引用的回答（远期，依赖访问控制设计成熟） |

## 3. 硬原则（立项时不得违背）

1. **人工确认**：AI 产物一律先进草稿态（预览 diff 或草稿块），用户显式接受才合入页面；
2. **页面即上下文**：输入构造 = 页面 snapshot（结构化 JSON）+ 必要的关联页摘要，不做隐式全库扫描（A6 除外，届时单独过权限设计）；
3. **成本可见**：每次调用记录 token 用量与模型（`ai_calls` 表，立项时设计），工作空间级月配额；
4. **供应商抽象**：Provider 接口 + 至少两家实现（含一家国产），模型名/密钥走环境变量；不写死任何厂商；
5. **异步执行**：生成类任务走队列（独立 worker 进程），前端轮询/SSE 展示进度；禁止在 API 请求线程内等待 LLM；
6. **失败降级**：LLM 不可用时相关入口隐藏即可，不阻塞任何基础编辑功能；
7. **语言跟随用户**：AI 输入/输出语言跟随当前用户 locale（13 §3），提示词内显式声明目标语言，不默认中文。

## 4. 技术形态预留

- worker 以独立 Bun 进程 + BullMQ（Redis）部署（compose 加 `worker` 服务，无端口，健康检查用队列探活）；用 BullMQ 原生 API，不引框架绑定；
- 提示词模板放 `packages/prompts`，版本化管理（每次改动记录效果用例）；
- 页面写入通过「快照 → 服务端以 update 形式合入」实现，与 08 §4 的写路径一致，**不另开旁路写通道**。

# 03 - 用户角色与权限

> 权威文档：角色与权限规则。会话与认证机制见 07 §5，表结构见 08 §3。

## 1. 设计原则：先简单，后精准

旧版权限体系（三级继承 + 项目角色 + 文档角色 + 权限缓存）是过度设计。新版权限只有一层：**工作空间角色**。

- 工作空间成员对空间内所有页面享有其角色对应的权限；
- 页面级权限、公开分享链接（public link）、访客（guest）全部推到后期，MVP 不做（见 §5）。

## 2. 角色

| 角色 | 定位 | 数量约束 |
|------|------|----------|
| **Owner** | 空间所有者：转让空间、删除空间（后期）、管理成员与角色 | ≥1，可多个 |
| **Admin** | 副管理员：除转让/删除空间外与 Owner 相同 | 不限 |
| **Member** | 普通成员：创建与编辑页面、管理标签、上传附件 | 不限 |

Viewer（只读成员）MVP 不做——小团队场景下价值低，等公开分享时一并设计。

## 3. 权限矩阵

| 操作 | Owner | Admin | Member |
|------|:-----:|:------:|:-------:|
| 修改空间名称/头像 | ✓ | ✓ | ✗ |
| 邀请成员 / 移除成员 / 改角色 | ✓ | ✓（不可动 Owner） | ✗ |
| 转让 Owner / 删除空间 | ✓ | ✗ | ✗ |
| 创建页面 / 编辑空间内任意页面 | ✓ | ✓ | ✓ |
| 删除页面（进回收站）/ 恢复 / 彻底删除 | ✓ | ✓ | ✓（仅自己创建的页面可彻底删除，MVP 简化为全员可彻底删除回收站内容亦可，实现时二选一并记录） |
| 管理标签（增删改） | ✓ | ✓ | ✓ |
| 上传附件 | ✓ | ✓ | ✓ |
| 管理模板页 | ✓ | ✓ | ✓ |

判定规则：

1. 取 `workspace_members.role`，直接决定权限，无继承、无覆盖、无缓存层；
2. 每次请求在 Hono 工作空间中间件中查一次成员表（PostgreSQL 单行索引查询，微秒级），**不引入 Redis 权限缓存**；
3. 未登录访问一律 401，非成员访问一律 403，API 错误码见 10 §6。

## 4. 成员生命周期

```
邀请（Owner/Admin 发送邀请链接，7 天有效）→ 加入（登录后接受）→ Member
   → 可升级 Admin/Owner（Owner 操作）
   → 被移除 / 主动离开（成员行删除，其创建的页面保留在空间内）
```

- 邀请链接：`/invite/{token}`，token 存 Redis（7 天 TTL），含空间 id 与邀请人 id；
- 注册用户点击即加入；未注册用户先注册再自动加入。

## 5. 后期路线（仅占位，不设计）

| 能力 | 说明 |
|------|------|
| 页面级权限 | 单页对成员/角色收窄（只读/隐藏） |
| 公开分享 | 只读 public link，可关停、可设密码 |
| 访客 Guest | 空间外用户被分享到单个页面树 |

## 6. 待细化

- 「彻底删除」的权限粒度（矩阵中已标注二选一，Phase 1 实现时定）。
- 附件配额（每成员/每空间上限）——MVP 先不限制，超量风险接受。

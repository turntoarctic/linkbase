# 09 - 实时协作设计

> 权威文档：WebSocket 与 Yjs 实时同步（**Phase 2 / P1-1** 启用；MVP 阶段服务端只需保证 doc REST 端点就绪，本路由不注册）。存储语义见 08 §4。
>
> ⚠️ **整体搁置（2026-09-30）**：编辑器现为 BlockNote JSON 模式（05），MVP 无实时同步；多标签页并发写 = last-write-wins。BlockNote 原生支持协作模式（yjs），本文件的 WS 房间/票据设计在需求成立时按其改造启用（05 §7），**现在不做任何预留代码**。

## 1. 目标

同一页面多人同时编辑：秒级互见、光标与选区可见、断线自动恢复、不丢内容。**服务端不理解块内容**——它是 Yjs 消息的转发器 + 持久化器，所有合并由 CRDT 保证。

## 2. 通道与鉴权

- 端点：`GET /ws`（升级请求，经 `hono/bun` 的 `upgradeWebSocket` 走 Bun 原生 WebSocket），**二进制帧**；
- 鉴权用**一次性票据**（避免长寿命 token 进 URL 日志）：
  1. 客户端 `POST /api/ws/ticket`（Bearer JWT）→ `{ ticket, expiresIn: 30 }`；
  2. 票据存 Redis `ws-ticket:{ticket} → { userId }`，TTL 30s，**取出即焚**；
  3. `wss://host/ws?ticket=...&workspaceId=...&pageId=...`；
- 服务端升级时校验：票据有效 + `workspace_members` 有该用户（03 §3）+ page 属于该空间且不在回收站 → 建立房间；任一失败以 close code 拒绝：

| close code | 含义 |
|------------|------|
| 4001 | 票据无效/过期 |
| 4003 | 无工作空间权限 |
| 4004 | 页面不存在 |

## 3. 房间模型

```
room key = `ws:{workspaceId}:page:{pageId}`
rooms: Map<key, { clients: Set<WebSocket>, doc: Y.Doc }>   # 进程内存，单实例
```

- 进程内维护该页的 Y.Doc 实例：进入房间时从存储装载（快照+增量合并，08 §4.1 的复用）；
- 第一个用户进入时装载，最后一个用户离开时：把内存 doc 的最终状态确保已持久（§5 的落库时机）→ 卸载；
- 单实例部署为 MVP 约束（04 §6）；多实例扩展方案预留见 §7。

## 4. 消息协议

直接使用 **y-protocols 标准编码**（与 y-websocket 同 wire format），不自造 JSON 协议：

| 消息类型（首字节） | 方向 | 服务端行为 |
|--------------------|------|-----------|
| sync step 1 (0) | C→S | 回 sync step 2：内存 doc 相对客户端 state vector 的差异 |
| sync step 2 (1) | C→S | 客户端差异合入内存 doc → 广播他人 → 持久化（§5） |
| update (2) | C→S | 同上 |
| awareness (3+) | 双向 | 原样转发给房间其他人（光标/选区/在线头像，服务端不解析） |

心跳：WS 协议层 ping/pong，服务端 30s 无 pong 踢出。

## 5. 持久化与落库时机

- 房间内每次合入 update → **去抖 500ms** 批量写 `page_updates`（多人高频编辑时合并写放大）；
- 用户离开/房间卸载 → 强制 flush 未落库增量；
- 快照合并仍由后台任务负责（08 §4.3），WS 路径不做快照；
- 崩溃容忍：最多丢 500ms 增量，客户端引擎会在重连时通过 pull 补推（Yjs update 双向幂等）。

## 6. 客户端接入（与 05 的衔接）

- `ServerDocSource.subscribe` 实现为：连接房间 → 收到 update 帧回调 `cb(docId, update)` → 引擎自动合入；
- 在线头像：`ServerAwarenessSource` 实现 `AwarenessSource`，编码 y-protocols awareness 消息收发；
- 断线重连：引擎自带的重试 + 退避；重连成功先 sync step1/2 全量对齐再继续；
- 未启用 WS 的 MVP 阶段：`subscribe` 返回空退订（05 §4 已兼容）。

## 7. 多实例扩展（预留，不实施）

房间状态在进程内存，多实例必须跨进程广播：房间消息发布到 Redis pub/sub 频道 `room:{key}`，各实例订阅自己有本地客户端的频道；Y.Doc 装载/卸载加 Redis 分布式锁防双装载。**在需要横向扩展前不做**，但禁止引入任何与单实例内存房间冲突的隐藏单例（如全局连接表被复用为业务状态）。

## 8. 验收标准（Phase 2）

1. 两浏览器同页编辑，1s 内互见（同机房网络）；
2. 光标/选区/姓名头像实时显示；
3. 一方断网 30s 继续编辑，恢复后内容自动合并且无冲突标记（CRDT 保证，验证不丢字）；
4. 服务端重启，客户端自动重连并恢复到最新状态；
5. 非成员持有效 JWT 尝试连接他人空间页面 → 4003 关闭。

## 9. 待细化

- 大房间（>20 人同页）的广播性能是否需要分片（预期场景罕见，先不做）;
- awareness 消息的默认字段约定（name/color/avatar，客户端实施时与 06 §5.5 的头像样式对齐）。
